# opendata-atlas Milestone 2: Portal Surface — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve every registered public Socrata portal from one server: a generated registry, a required `portal` argument on every data tool, a new `atlas_find_portals` tool, per-dataset knowledge reporting, and served text that is portal-aware. Seattle keeps its behavior apart from the differences this design specifies.

**Architecture:** A shipped `registry.json` (generated by `scripts/build_registry.py`) plus the knowledge packs define the reachable portals. Each tool call resolves its `portal` argument to a `PortalContext` (`portals/resolve.py`); the engine already takes that context everywhere (milestone 1). Results echo `source.portal`; describe and query report knowledge levels computed from pack claims.

**Tech Stack:** Python ≥3.12, uv, FastMCP 4 on MCP SDK v2, Pydantic, httpx, ijson, anyio; ruff, ty, prek; pytest with the record/replay `tests/http_fixtures.py`.

**Spec:** `docs/design.md` (with `docs/decisions.md`, `docs/upstream-facts.md`). Carry-over inputs: `docs/superpowers/plans/2026-10-17-m2-carryover.md`. Standards: `~/projects/skills/agent-friendly-mcp/` and `~/projects/skills/separating-context-from-constraints/`.

**Scope notes:**
- **Freshness is milestone 3.** Runtime freshness needs `validation.json`, which milestone 3's drift run produces. In this plan every claim reports `validation: "unchecked"` and no verdict is degraded. The capability-summary sentence about drift checks and installed releases also ships in milestone 3.
- **Out of scope:** the profiler, checkers, drift job, curation skill, knowledge-gap head rule (milestone 3); Chicago curation (milestone 4); release (milestone 5).
- **Base branch:** `docs/design` (the repo has no `main` yet). Work on `feat/portal-surface`.

## Review Focus

1. **`portal` given in mixed case (`"Seattle"`, `"DATA.SEATTLE.GOV"`)** → resolves to Seattle; `" seattle"` (whitespace) fails the input pattern with `invalid_argument`, not `portal_not_found`. Test in Task 3.
2. **Two registry entries claiming the same alias** → `build_registry.py` exits non-zero naming both entries; it never writes an ambiguous registry. Test in Task 2.
3. **Paging with the alias on page 1 and the canonical id on page 2** (or the reverse) → the continuation is accepted. Test in Task 5.
4. **A portal with a knowledge pack but no registry entry** (e.g. a manually curated portal the enumeration misses) → it is still reachable, and its pack's `portal.toml` identity wins over any registry entry with the same id. Test in Task 1.
5. **`atlas_find_portals` with a query matching nothing** → a success result with `candidates: []`, `has_more: false`, never an error. Test in Task 6.

### Task 6: `atlas_find_portals`

**Files:**
- Create: `src/opendata_atlas/core/portals.py` (search logic), `tests/test_find_portals.py`
- Modify: `src/opendata_atlas/mcp/tools.py`, `core/models.py`, `core/reference.py` (`ERROR_CODES_BY_TOOL`, `ERROR_EXAMPLES`), `tests/test_contract.py` (`EXPECTED_TOOLS` order: find_portals first), `tests/snapshots/tools_list.json`, `CHANGELOG.md`

**Interfaces:**
- Consumes: `load_registry`, `Registry.ordered`, `cursor.encode/decode`.
- Produces:
  - `PortalCandidate(Closed)`: `id`, `aliases: list[str]`, `name`, `jurisdiction: Jurisdiction | None` (reuse the portal model's type), `tier`, `timezone: str | None`, `dataset_count: int | None`, `match: Literal["alias","name","place_name","host"] | None` (`None` when listing without a query).
  - `FindPortalsResult(Open)`: `candidates: list[PortalCandidate]`, `has_more: bool`, `next_cursor: str | None`, `registry_version: str`, `source: Source` (no `portal`).
  - Tool `atlas_find_portals(query: str | None = None (1–100), level: Literal[...] | None = None, country: str | None = None (2 letters), tier: Literal["generic","profiled","curated"] | None = None, page_size: int | None = None (1–50, default 10), cursor: Cursor = None) -> FindPortalsResult`; annotations read-only, `openWorldHint: false`; first in tool order.
  - `find_portals(registry, *, query, level, country, tier, page_size, cursor) -> FindPortalsResult` in `core/portals.py`. Matching (case-insensitive, whole-token): exact alias or id → `alias`; all query tokens in `name` → `name`; in any `place_names` entry → `place_name`; substring of `public_host` → `host`. Ordering: match strength (`alias` > `name` > `place_name` > `host`), then tier (curated > profiled > generic), then canonical id. No query: curated, then profiled portals only (unless `tier` asks for generic).
  - Cursor kind `"portals"` with `portal_id="*"`, state: filters + offset + `registry_version`; a different current `registry_version` → `cursor_expired` with the `read_paging` repair.
  - Ambiguity is served by returning every match, never by choosing: if two portals both match a place name, both are candidates, distinguished by `jurisdiction.level`. Tests pin behavior on fixture registries; which real portals share a place name depends on the overrides written in Task 2.
